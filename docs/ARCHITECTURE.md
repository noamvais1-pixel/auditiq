# ארכיטקטורה

## מסלול הבקשה

```
שאלה
  │
  ├─ 1. הסרת מידע מזהה          security/pii.py
  │     ת.ז, ח.פ, טלפון, אימייל, בנק, אשראי → מציינים הפיכים
  │
  ├─ 2. אחזור היברידי            rag/retriever.py
  │     BM25 (עברית מנורמלת) + אמבדינגס צפופים, איחוד ב-RRF
  │     קיבוע מזהים מפורשים: "תקן 27" מקבע את תקן 27
  │
  ├─ 3. שער כיסוי — שכבה 1       rag/coverage.py
  │     אין חפיפה לקסיקלית → סירוב, ללא קריאה למודל
  │
  ├─ 4. יצירה                    llm/providers.py
  │     Gemini או Anthropic, אותו ממשק
  │     לולאת כלים: מע"מ, פחת, מהותיות, ערך נוכחי
  │
  ├─ 5. אימות ציטוטים            llm/guardrails.py
  │     מזהה שלא היה בהקשר → מוסר ומדווח
  │     תשובה מהותית ללא ציטוט תקף → מומרת לסירוב
  │
  ├─ 6. רישום ביקורת             security/audit_log.py
  │     שרשרת גיבובים, ללא הטקסט הגולמי
  │
  └─ 7. השבת הערכים המקוריים
        אחרי הרישום, כדי שהלוג לא יחזיק את מה שנועד להגן עליו
```

הסדר הוא כל התכנון. שני פרטים שקל לפספס:

**ההסרה לפני האחזור, לא רק לפני המודל.** שאילתת האחזור יוצאת לספק האמבדינגס
המארח בדיוק כמו הפרומפט.

**ההשבה אחרי הרישום.** אחרת הלוג הופך לעותק שני של נתוני הלקוח.

## החלטות ולמה

### עברית מנורמלת ב-BM25 — `rag/hebrew.py`

טוקנייזר סטנדרטי מתייחס לעברית כאל שקיות מחרוזות אטומות, וזה שובר recall בשקט.
שלושה טיפולים: קיפול אותיות סופיות, הפשטת תחיליות ו/ה/ב/ל/כ/מ/ש, וגזירת ריבוי
וסמיכות. הכול היוריסטי ולא מנתח מורפולוגי — אין מודל להוריד ואין רישיון לסדר,
והוא מחזיר את רוב ה-recall שמנתח אמיתי היה מחזיר.

מגבלת שלוש אותיות בגזע היא מה שמונע מ-`פחת` להיגזר ל-`פח`.

### חלוקה לפי מבנה — `rag/chunker.py`

חלון של 800 תווים הוא הכלי הלא נכון כאן. המסמכים כתובים כהיררכיה ממוספרת —
`17` / `17(א)` / `17(א)(2)` — והמספר **הוא** הדרך שבה רואה חשבון מצטט תשובה.
פיצול באמצע סעיף מייצר קטעים שאי אפשר לצטט, ואז בודק הציטוטים פוסל תשובות טובות.

כל קטע נושא פירורי לחם של הכותרות שמעליו, והם מוצמדים לטקסט שנשלח לאמבדינג —
סעיף חשוף כמו "שיעור זה יחול גם על נכס שנרכש בשנת המס" חסר משמעות בלי לדעת באיזה
פרק הוא יושב.

### RRF ולא סכום משוקלל — `rag/retriever.py`

ציוני BM25 וקוסינוס חיים על סקאלות שאינן ברות השוואה; כל משקל קבוע מכויל לקורפוס
אחד ושגוי בשקט בבא אחריו. RRF משתמש בדירוג בלבד ולכן אינו דורש כיול.

המשקל היחיד שאינו חינם הוא **כמה כל שולף זכאי להצביע**. ראה
[EVALUATION.md](EVALUATION.md) — הגיבוי הלקסיקלי המקומי מקבל 0, ספק סמנטי אמיתי
מקבל 1.0, ושניהם נמדדו ולא נוחשו.

### שיעורים בנתונים, לא בפרומפט — `llm/tools.py`

מודל שנשאל מה שיעור המע"מ עונה מנתוני האימון, כלומר מתצלום של שנה כלשהי.
השיעורים יושבים ב-`data/rates/rates.json` ומתוארכים: שאלה על חשבונית מ-2024
מקבלת 17%, ואחת מ-2025 מקבלת 18%, בלי שהמודל יידע אף אחד מהם.

כל כלי מחזיר את הקלטים לצד התוצאה, כדי שהתשובה תהיה ניתנת לביקורת — הסוקר רואה
איזה שיעור הוחל ומאיפה הגיע, לא רק את השורה התחתונה.

### ספק כשורת קונפיג — `llm/providers.py`

סכמות הכלים, הפרומפט, בודק הציטוטים ורשומת הביקורת אינם תלויי ספק. רק פורמט
החוט שונה. בסביבה מוסדרת בחירת המודל משתנה מסיבות רכש, לא טכניות, ואז לא רוצים
לבדוק מחדש את כל השאר. `LLM_PROVIDER=gemini|anthropic` היא כל ההחלפה.

מצב ההדגמה הוא ספק ככל ספק אחר, ולא מקרה מיוחד שמושחל עם `if` דרך הקוד האמיתי.
